Uposatha Version 17 · 29 October 2026

Added six complete English reading texts, adjustable font size (16–30 px),
paper/night themes, automatic on-device chapter/position retention, and Read
navigation. Every text carries translator/source information. The Dhammapada
contains all 423 verses in 26 chapters. Five SuttaCentral translations are CC0;
the Heart Sutra is a labelled new rendering from the Chinese T 251 recension.

Automated validation: 47 passing checks
- 18 existing playback and package checks.
- 17 GitHub Pages/service-worker checks, extended to verify reader resources
  and the full reading catalogue while offline at / and /uposatha/.
- 8 reading checks: source Git hashes, no dropped translation segments,
  all 423 verses exactly once, deterministic regeneration, storage failures,
  progress/preferences round-trip, and offline integration.
- 4 AWS installer tests in isolated temporary directories: checksum rejection,
  backup/apply/rollback, automatic restore after a simulated write failure,
  and refusal to modify an unexpected recording set.

Browser validation in an installed-app preview harness:
- All six reading cards and navigation render.
- Dhammapada chapter switching, 22 px text and night mode work.
- Closing/reopening restores the saved chapter and scroll position.
- Heart Sutra content and its new-translation credit render correctly.
- Reader header layout checked against the complete dialog width.

The preview harness is not shipped. Local audio test files are sparse fixtures
because the GitHub read connector does not return large binary contents.
No fixture media is part of the update or published changes. All 20 existing
GitHub recording blobs are retained unchanged; the hosted CI tests use the real
repository recordings. Offline worker tests use simulated network/cache APIs.
Physical Android/iOS PWA installation was not tested in this environment.

AWS deployment: the app is portable to the existing root. Installer uses
/srv/uposatha-download, keeps a full dated /srv/uposatha-backup-* snapshot,
retains old assets for open tabs, validates all payload checksums, and restores
the previous shell on a write/verification failure. No service restarts and no
Caddy configuration edits are performed. The standalone --source-commit flow
downloads all media from a pinned public GitHub release; the ZIP can reuse only
matching existing recordings. Remote AWS installation requires running the
installer on the server; no connected server shell was available here.
